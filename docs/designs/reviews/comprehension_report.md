### Feature Spec Paraphrase

**What this proposes**
This document proposes a four-phase sequential refactoring plan for the Huntress Godot 4.x greybox vertical slice to eliminate cross-component couplings and shallow wrapper layers before implementing boss encounters (`SPEC-005`) and village contracts (`SPEC-006`). First, it moves temporal invulnerability tracking out of `PlayerDodgeState` into `HealthComponent` using string-tagged leases (`_active_iframes: Dictionary`) and adds `pierces_invulnerability_tags` to `AttackData`, freeing `HurtboxComponent` from player-specific references. Second, it introduces a virtual `can_enter(from_state: State) -> bool` admission check on `State` (evaluated inside `StateMachine.transition_to()`) along with `can_cancel_into_dodge()`, so sibling states (`PlayerIdleState`, `PlayerMoveState`, `PlayerAttackState`) can request transitions to `DodgeState` without holding direct references to `PlayerDodgeState`. Third, it unifies world interaction objects (`InteractableClue`, `InteractableReagent`, `InteractableCampfire`) under an `Interactable` (`Area2D`) base class with a composite focus relevance formula combining priority, squared distance, facing alignment, and a 12px foot-touch bonus. Fourth, it replaces the `RefCounted` `PreparationManager` with an instance-duplicated `PreparationData` (`Resource`) featuring primitive dictionary serialization (`to_dict()` / `from_dict()`), eliminating pass-through boilerplate in `InventoryComponent` and registering the two missing `SPEC-004` test suites in the headless CLI test runner.

**How the existing system works, per this document**
Currently, `HurtboxComponent` holds an explicit `@export var dodge_state: PlayerDodgeState` reference and checks `dodge_state.is_invulnerable()` before applying damage, while `HealthComponent` tracks invulnerability with a single `_invulnerability_timer: float`. In the finite state machine, `PlayerIdleState`, `PlayerMoveState`, and `PlayerAttackState` each hold a direct `@export var dodge_state: PlayerDodgeState` reference to query `dodge_state.can_dodge()` and consume the 0.15s dodge input buffer. For world interactions, `PlayerInteractionComponent` maintains three separate typed arrays (`_overlapping_clues`, `_overlapping_reagents`, `_overlapping_campfires`), three focus pointers, and a fixed `if/else` chain in `try_start_interaction()`. Finally, `InventoryComponent` wraps a `RefCounted` `PreparationManager`, manually copying `@export` parameters into it and forwarding over a dozen methods one-to-one, while `tests/unit/run_tests.gd` omits `TestPreparationManager` and `TestReagentAndCampfire`.

### Detailed Implementation Paraphrase

**What this proposes**
The Detailed Implementation Plan specifies modifications across 25 target files (creating 2 new scripts and updating 23 existing scripts, scenes, and test suites) mapped to the four refactoring phases, followed by a three-step verification plan. Phase 1 updates `health_component.gd`, `attack_data.gd`, `hurtbox_component.gd`, and `player_greybox_visual.gd` (ensuring post-hit alpha blinking responds only to the `&"post_hit"` tag rather than `&"dodge"` leases). Phase 2 updates `state.gd`, `state_machine.gd`, `player_dodge_state.gd`, `player_idle_state.gd`, `player_move_state.gd`, `player_attack_state.gd`, `player.gd`, and `player.tscn` to wire `dodge_state.health_component`, remove serialized `dodge_state` `NodePath` assignments, and gate transitions through `State.can_enter()`. Phase 3 creates `src/entities/world/interactable.gd`, migrates `interactable_clue.gd`, `interactable_reagent.gd`, and `interactable_campfire.gd` to extend `Interactable`, and updates `player_interaction_component.gd` to use `_overlapping_interactables` and `compute_interactable_score()` while retaining legacy signals for compatibility. Phase 4 creates `src/data/preparation_data.gd`, turns `preparation_manager.gd` into a backward-compatible subclass of `PreparationData`, updates `inventory_component.gd` to duplicate `preparation_data` on initialization, and updates five unit test files (`test_combat_components_and_states.gd`, `test_player_state_machine.gd`, `test_interaction_and_clues.gd`, `test_preparation_manager.gd`, and `run_tests.gd`) so all 8 unit test suites and 3 greybox sandboxes pass headless and interactive checks.

**How the existing system works, per this document**
In the current codebase files, `player.gd` and `player.tscn` wire `dodge_state` directly into `HurtboxComponent`, `IdleState`, `MoveState`, and `AttackState`, and `player_greybox_visual.gd` triggers post-hit invulnerability blinking whenever `HealthComponent` is invulnerable. `InteractableClue`, `InteractableReagent`, and `InteractableCampfire` directly extend `Area2D` with class-specific methods (`complete_inspection()`, `collect_reagent()`, `activate_campfire()`), and `PlayerInteractionComponent` selects clues via `select_best_clue`. `PreparationManager` is a standalone class instantiated by tests and wrapped by `InventoryComponent`, and the unit test rigs (`_build_combat_rig()`, `_build_test_rig()`) manually wire `dodge_state` into sibling states and the hurtbox.
